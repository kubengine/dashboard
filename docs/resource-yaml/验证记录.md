## 真实资源与页面

使用独立配置、数据库和登录会话进行开发验证，再直连生产页面验证。两次分别创建唯一命名、带验证标签的临时 ConfigMap，仅修改这些临时资源，不修改现有业务资源。

1. 页面将 `data.mode` 从 `initial` 改为 `updated-from-ui`，删除 `data.obsolete`，填写说明。
2. dry-run 后先读取实际对象，确认尚未写入；差异表准确显示两个字段及前后值。
3. 确认应用后，版本 v1 可查，操作人、说明、resourceVersion、字段差异和快照正确。
4. 再打开编辑器，模拟另一个请求修改同一对象；旧草稿预览返回冲突，草稿仍保留。
5. 确认放弃修改有效；375px 预览弹窗无整页横向溢出，差异表内部滚动。
6. 生产库中 v1、v2 均为 applied，快照不含测试配置明文；解密后内容正确，独立密钥为 0600。
7. 两个测试 ConfigMap 均按标签与 UID 校验后删除；测试登录已退出，浏览器与本地 API 已关闭。生产审计记录按设计保留。
