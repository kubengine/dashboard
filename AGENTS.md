# AGENTS.md

Guidance for AI agents working in the **KubeEngine Dashboard** repository — a React + Umi Max frontend for a container-cloud management platform.

## Project Overview

Frontend for KubeEngine (容器云管理平台), built with **React 18 + Umi Max 4 + Ant Design 5 + TypeScript 5**. It manages Kubernetes clusters, Helm-based application deployment, and container image/Helm-chart artifacts. The UI is almost entirely in **Simplified Chinese** — keep user-facing strings (labels, messages, errors, route `name`s) in Chinese to match.

## Architecture & Control Flow

### Umi Max plugins (all enabled in `.umirc.ts`)

`antd`, `access`, `model`, `initialState`, `request`, `layout`, `dva`. These power the cross-cutting concerns below — prefer their built-in patterns over rolling your own.

### Routing — config-based, NOT conventional

Routes are defined explicitly in `.umirc.ts` under `routes` (despite README claims of convention-based routing — that is inaccurate). Each route maps a `path` to a `component` under `@/pages`. Detail/list pages use path params (e.g. `:app_id`, `:cluster_id`, `:namespace/:name`). Use `hideInMenu: true` for child/detail routes that should not appear in the sidebar. Menu items are derived from `name` + `icon` on each route.

### Authentication — dual-mode, globally intercepted

Two auth modes coexist, selected at login and stored under a single `localStorage` key:

- **Token (JWT)** — default. `src/utils/auth.ts` stores `{ authType, token }` in `localStorage['PRO_AUTH_STORE']`.
- **AKSK** — Access/Secret Key with request signing (`src/utils/aksk.ts`): `HMAC-SHA256(ak+timestamp+nonce, sk)`, Base64-encoded and URL-safe (`+`→`-`, `/`→`_`, stripped `=`). Headers sent: `ak`, `timestamp`, `nonce`, `signature`.

Auth is wired entirely in `src/app.ts`:

- `getInitialState()` seeds the global initialState with current user/auth info.
- `layout.onPageChange` is the **route guard** — redirects to `/user/login` when token is expired/absent or AK/SK missing. Whitelist: only `/user/login`.
- `request.requestInterceptors` injects auth headers based on `authType`.
- `request.responseInterceptors` auto-refreshes the token when the backend returns `new_access_token`, and handles non-200/401 globally.
- `request.errorConfig` maps HTTP 401/403/500/network errors to antd `notification`.

**Important:** The global request/response interceptors mean service functions (`src/services/*`) should generally **not** add their own auth headers or error handling — that is centralized. Service functions destructure `{ code, data, message }` from the `API.Result` envelope (see below).

### API service layer (`src/services/`)

- Pattern: one `*Controller.ts` file per backend domain (UserController, AppController, KubernetesController, ArtifactsController). Each exports async functions calling `request()` from `@umijs/max`.
- All controllers are aggregated and re-exported as the default object in `src/services/index.ts` → consumed as `services.AppsController.list(...)`, `service.UserController.login(...)`. Both naming styles (`service` / `services`) appear in pages.
- **API envelope:** every endpoint returns `API.Result = { code, message, data, new_access_token?, token_type? }`. Pages check `if (code == 200)` (loose equality) and read `data`. **Note:** backend uses `code == 200` (number), compared with `==` throughout — keep consistent.
- **Type definitions** live in `src/services/typings.d.ts` under the global `API` namespace (`API.LoginParams`, `API.LoginResult`, `API.Result`). Domain DTOs (e.g. `App`, `AppFieldConfig`) are exported from their controller file (`AppController.ts`) and imported as named values.
- Base path: all API URLs start with `/api/v1/...`. Dev proxy in `.umirc.ts` forwards `/api` → `http://172.31.57.23:8080/` (with WebSocket support `ws: true`). Adjust this target when pointing at a different backend.
- Endpoints follow REST-ish verbs: `/list`, `/get/:id`, `/add`, `/update`, `/del/:id`.

### State management

- **Global app state** via Umi `initialState` plugin — `useModel('@@initialState')` gives `{ initialState, setInitialState }`. Used for current user/auth info; updated on login/logout.
- **Custom models** in `src/models/` using Umi's function-style `useModel`. Example: `websocket.ts` exposes `connect/sendMessage/close/...` consumed via `useModel('websocket')`. WebSocket connects to `/api/v1/ws` with the bearer token passed as a `?token=` query param (it cannot use HTTP headers), and has built-in auto-reconnect.

### Styling

- **CSS-in-JS** via `antd-style` (`createStyles` / `useStyles`), using antd design tokens (`({ token }) => ...`). This is the dominant pattern in pages — prefer it over external CSS.
- `src/global.less` for global styles. `.less` files are linted by stylelint.
- Logos / static images live in `public/assets/` and `public/app_logo/` (referenced as `/assets/...` and `/app_logo/...`).

## Code Conventions

- **Language:** TypeScript everywhere (`.ts`/`.tsx`). User-facing strings in Chinese.
- **Imports:** sorted automatically by `prettier-plugin-organize-imports` — do not hand-order imports.
- **Formatting:** Prettier — single quotes, trailing comma `all`, 80-col print width (`.prettierrc`).
- **React:** functional components with hooks; `React.FC` typing; `useEffect` + `useState` for data fetching (no React Query / SWR). Loading state via a local `useState<boolean>(false)` toggled in try/finally.
- **Naming:** controller files are PascalCase (`AppController.ts`); their exported functions are snake_case (`get_cluster_by_id`, `list`, `deploy`). Local component files are PascalCase (`Store.tsx`, `ClusterDetail`).
- **Pagination** is manual: pages track `{ current, pageSize }` in local state and pass them to service functions; total comes back in `data.total`.

## Gotchas & Non-Obvious Details

- **`.umirc.ts` is the single source of truth** for routes, layout, proxy, and enabled plugins. It is NOT split into `config/` despite some README references — there is no `config/` directory.
- **The README is partially inaccurate.** It describes convention-based routing, a `config/proxy.ts`, and a `mock/` directory that do not exist in this repo. Trust the actual files over the README.
- **`.npmrc` points at a private registry** (`http://172.31.54.1:8081/...`) — installs will fail without access to it. A commented-out public mirror (`registry.npmmirror.com`) is included as a fallback.
- **`src/.umi/` is generated** by `max setup`/`max dev` and gitignored. Path alias `@/*` → `src/*` and the global `API` namespace come from here. Don't edit; regenerate if stale.
- **Password-free login** (`src/pages/User/Login/PasswordFree.tsx`, route `/pf/login`) hardcodes admin credentials — intended only for specific SSO/internal scenarios, not a feature to extend casually.
- **WebSocket auth** passes the token as a URL query param (browser WS API cannot set headers), unlike the REST flow which uses headers.
- **App field configs** (`AppFieldConfig` in `AppController.ts`) drive a dynamic form system (see `src/pages/Apps/components/DynamicForm.tsx`). These configs map form fields to Helm values via `helm_props.keys` and `helm_props.type`. When editing app-deployment forms, respect this schema — `field_props` is an open `{ [key: string]: any }` catch-all.
- **Loose equality `==`** is used consistently against the numeric `code` field (e.g. `code == 200`). Keep using `==` for these checks to match the codebase style.
